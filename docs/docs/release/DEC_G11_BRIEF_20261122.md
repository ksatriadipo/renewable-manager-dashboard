Status: **PROPOSED**. Records only. Nothing in code, config or switches was changed while preparing this brief.
`CandidateViewG11.InterviewVisible` stays **OFF** until the Director decides.

Register row: `DEC-G11` in `docs/remediation/TASK_REGISTER.md` (Blockers and risks), linked task `B2-11` (patch
`b2_g11_cand_r505`). Codex screening SG-36efd6a91a8e asked for this brief.

## 1. What G11 / U1-028 / the switch are

- FACT: G11 = root-cause group "candidate counts come from different filters" (RC-U1-15), findings U1-026 and U1-028
  (`docs/remediation/ROOT_CAUSE_ANALYSIS.md` G11 row; `docs/remediation/MASTER_REMEDIATION_BACKLOG.md` U1-028 row).
- FACT: U1-028 (capture `15_interview`): the interview modal's "Hasil wawancara" column compares the CV (`ClaimedSkills`)
  with the candidate's **true** skills (`Person.Skills`), while the candidate card shows `Candidate.VisibleSkills`
  (revealed values after an interview, otherwise the claimed values). The two screens use different data, and the modal
  leaks the true skills (RCA `/srv/rm/scratch/wip_b2_rca_g11/RCA_G11.md` §1 rows I/J, §2).
- FACT: GDD sketch 8 says the interview reveals skills with an accuracy that depends on the interviewer ("hasilnya lebih
  akurat jika pewawancara ..."); RCA §2 concludes the modal should use `VisibleSkills`, like the card.
- FACT: patch `b2_g11_cand_r505` (manifest `repo_tools/docs/release/patches/b2_g11_cand_r505.patch.manifest.md`) added
  two static switches in `Core/Simulation/Company.CandidateView.cs`:
  - `CandidateViewG11.Counts` — default ON: one Core source for candidate counts (U1-026).
  - `CandidateViewG11.InterviewVisible` — default **OFF**: `Company.InterviewResultSkills(c)` returns `VisibleSkills`
    when ON, true skills when OFF (legacy). Marked "NEEDS OWNER DECISION" in the manifest because it is player-visible.
- FACT: tested revision state (register B2-13 note, b2r5b on game `de139b0`): `InterviewVisible = false`, `Counts = true`.
- FACT: Auditor B2-05 (`docs/remediation/batch02/B2_05_AUDITOR_REVIEW.md`, r505 PASS_WITH_CONDITIONS): U1-028 is not
  fixed while the switch is OFF and must stay OPEN/PENDING_DECISION (condition C-8); the visible title-count change on
  `14_hire_board` is NOT_TESTED (C-9).

## 3. Recommendation (PROPOSAL)

PROPOSAL: **A for the D1 internal APK / closed test, with B scheduled as its own reviewed patch round** (capture variant
ON + Auditor + owner visual). Reason: the triage record (`docs/remediation/BLOCKER_TRIAGE_20261122.md` row 7) lists
"ship with the switch OFF" as an independent workaround and the switch blocks only the U1-028 part of B2-11, while B is
a player-visible gameplay change that needs evidence the project does not have yet (C-8/C-9 open, no ON capture).
INFERENCE (MEDIUM): B matches the GDD sketch 8 intent and closes the information leak, so it is the likely long-term
answer. The Director decides.
