# Renewable Manager — Task Register (U37H remediation era)

Authoritative task record for the Command Center dashboard. The dashboard is a projection of this file: it never
stores a second copy of a task's status. One table row per task; a task ID is never reused or renamed, and a task is
never deleted (use CANCELLED). After a meaningful change, edit the row (Status / Visual / Evidence / Updated) and run
`python3 -m rmct sync --event task_status --ref <ID>` on the VPS (the 15-minute timer also re-reads this file).

Seeded 21 Nov 2026 from the Command Center adapter inventory without status changes (values as curated from the
board, decision register, batch reports and runner evidence on 21 Nov). Rows changed on the board after that seed
(for example B3-01 after decision E-39) are updated here by the orchestrator, not by the dashboard.

Rules:
- `Status`: NOT_STARTED, READY, IN_PROGRESS, IMPLEMENTED, TESTED, ACCEPTED, BLOCKED, ON_HOLD, DEFERRED, CANCELLED,
  REJECTED, NEEDS_REWORK. IMPLEMENTED (code exists), TESTED (runner EditMode/regression pass) and ACCEPTED
  (owner/Auditor acceptance) are separate states; a patch row is raised to TESTED by the dashboard only on runner
  evidence (committed by the runner in a round with 0 EditMode failures and no rollback).
- `Visual`: VISUALLY_ACCEPTED, NEEDS_RECHECK, NOT_TESTED, FAIL, N/A (N/A = no player-visible change). Seed: patch
  rows NOT_TESTED, other rows N/A, until a capture review records otherwise.
- DONE (dashboard) = Status ACCEPTED and Visual VISUALLY_ACCEPTED or N/A.
- Denominator for every percentage = all rows below except CANCELLED.
- Empty cell = not recorded (the dashboard shows NOT_RECORDED). Lists are space-separated. `Doc` = repo-relative
  Markdown path that holds the evidence; it is published with the dashboard after the secret/PII gate.
- Blockers: one row per blocker/risk; when resolved set Status RESOLVED and the Resolved date. Rows are never deleted.
  Priority seed rule: severity HIGH → P1, MEDIUM → P2, LOW → P3 (P0 only when a record says so).
- Status history: append a row when a status changes outside a sync run (optional; the dashboard also records every
  change it observes with its timestamp).
